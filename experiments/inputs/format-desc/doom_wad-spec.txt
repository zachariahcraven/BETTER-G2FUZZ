Doom WAD (id Software Doom/Doom II map and resource archive), as read by the Doom engine. All integers are little-endian. File layout: a 12-byte header (4 ASCII bytes "IWAD" or "PWAD"; int32 number of lumps; int32 offset of the directory), the lump data, and the directory: one 16-byte entry per lump (int32 file offset, int32 size in bytes, 8-byte ASCII name padded with NUL bytes). An add-on map WAD is a PWAD whose directory holds a map: a zero-size marker lump named MAPxx (Doom II, xx = 01-32) or ExMy (Doom), followed in this order by the map lumps THINGS, LINEDEFS, SIDEDEFS, VERTEXES, SEGS, SSECTORS, NODES, SECTORS, REJECT, BLOCKMAP. Record formats: THINGS 10 bytes each (int16 x, y, angle in degrees, type, flags; type 1 = player 1 start, which every playable map needs); LINEDEFS 14 bytes (uint16 start vertex, end vertex, flags, special, tag, right sidedef, left sidedef, 0xFFFF = none); SIDEDEFS 30 bytes (int16 x offset, y offset; 8-byte upper, lower and middle texture names, "-" = none; uint16 sector); VERTEXES 4 bytes (int16 x, y); SEGS 12 bytes (uint16 start vertex, end vertex; int16 angle; uint16 linedef; int16 direction 0/1; int16 offset); SSECTORS 4 bytes (uint16 seg count, first seg); NODES 28 bytes (int16 partition x, y, dx, dy; right bounding box and left bounding box as 4 int16 each: top, bottom, left, right; uint16 right child, left child, bit 15 set = subsector index); SECTORS 26 bytes (int16 floor height, ceiling height; 8-byte floor and ceiling flat names; int16 light level, special, tag); REJECT is a bit table of sector-to-sector visibility, ceil(sectors^2 / 8) bytes; BLOCKMAP is int16 origin x, origin y, number of columns, rows, then one uint16 offset per block to a list of linedef indexes that starts with 0 and ends with 0xFFFF. Sectors must be closed by linedefs; SEGS, SSECTORS and NODES form the BSP tree a node builder computes from the lines; texture and flat names must exist in the base game.
